# Hi-res Cel-Shaded Characters — Implementation Plan (Plan A: characters)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the six agents' 36×39 sprites with higher-resolution, cel-shaded 3D
sprites approaching the user's reference sheet, and integrate them into the live dashboard
with correct sizing/positioning — keeping the roster and tool→agent mapping unchanged.

**Architecture:** All sprite art is generated by `py/gen_sprites.py` (parametric grids +
`shade_hair`/`shade_body`/`fringe` + `render_cells`), previewed as PNGs, then `--emit`ed
into `js/app.js` as baked string-arrays drawn pixel-by-pixel on a vanilla 2D canvas. This
plan enlarges the generator's canvas, re-tunes geometry + shading for the new size, then
syncs `app.js` (color map, `FORM_KEYS`, sprite scale, and every position constant).

**Tech Stack:** Python 3 stdlib (`zlib`/`struct`/`math`) for generation + PNG preview;
vanilla canvas JS in `js/app.js`. No build step, no framework, no npm, no node (CLAUDE.md §1).

**Scope (this plan = spec Phases 0–2):** [spec](../specs/2026-06-06-hires-cel-shade-design.md)
Phase 0 resolution prototype → Phase 1 all six sprites → Phase 2 port + integrate. Scene
assets (spec Phases 3–4) are **Plan B**, written after Task 9's checkpoint.

**Verification model (no test framework):** the "tests" are
(a) `py/gen_sprites.py` `validate()` + `all_frames_uniform()` (width/height invariants),
(b) **render a PNG and Read it** (CLAUDE.md §6), (c) the live page renders without a
`const` collision / sprite-width error. Every art task ends with a render-PNG checkpoint.

## Task 1: Lock the new canvas size (Phase 0 — gating)

**Files:** Modify `py/gen_sprites.py` (constants `W`, `HEADH`, body rows, `LEGS_CUTE`,
preview `SCALE`).

- [ ] **Step 1 — Parameterize size.** Replace the hard-coded `W=36; HEADH=26; cx=17.5`
  with a single scale knob so geometry can grow uniformly:

```python
SZ = 2                      # resolution multiplier vs the original 36-wide art
W = 36*SZ; HEADH = 26*SZ; cx = (W-1)/2
```

  Then make every literal coordinate in `make_head`/`build_hair`/`fringe`/`make_body`/
  `make_back`/`make_body_back`/`skin_shade` and the eye/mouth/outfit stamps scale by `SZ`
  (multiply row/col literals and radii by `SZ`; `cx`/`cy` already derived). Work through the
  file top-to-bottom; this is mechanical but exhaustive — no literal pixel position may
  remain un-scaled. `LEGS_CUTE` rows: regenerate at `W` width and `4*SZ` rows.

- [ ] **Step 2 — Validate invariants.** Run: `py py/gen_sprites.py`
  Expected: prints `all frames uniform: <39*SZ>x<36*SZ>` and writes both PNGs with **no**
  `WIDTH`/`CHAR`/height-assert errors. If it errors, fix the offending grid's width/row count.

- [ ] **Step 3 — Render & view at new size.** Read `__cute_preview.png` and `__back_preview.png`.
  Expected: six characters intact (face, hair, outfit, legs) at 2× the pixels — blocky but
  whole. Note any geometry that broke in scaling (e.g., eyes off-center, mouth row wrong).

- [ ] **Step 4 — Iterate geometry until clean.** Adjust scaled constants and re-render
  (Steps 2–3) until each character is proportioned correctly at the new size. Acceptance:
  validate passes AND all six read as the prior design, just larger.

- [ ] **Step 5 — Checkpoint (USER).** Present both PNGs. Confirm `SZ` (canvas size) is the
  right detail budget vs the reference before investing in detail. If the user wants more
  detail, raise `SZ` and repeat. **Do not proceed until size is approved.**

- [ ] **Step 6 — Commit the parameterization.**


## Task 2: Re-tune hair shading for the new resolution

**Files:** Modify `py/gen_sprites.py` (`shade_hair` constants, `fringe` profiles).

- [ ] **Step 1 — Scale lock/ridge density.** In `shade_hair`, the `nlocks` per-style map and
  `fringe` depth literals were tuned for 36px. At higher res a lock should stay ~3–4px wide,
  so scale lock counts and fringe depths with `SZ`:

```python
# in shade_hair SP map: multiply each nlocks by ~SZ so locks stay the same on-screen width
nlocks,cdx,rw = SP.get(style,(6.5,0.0,0.40)); nlocks*=SZ; cdx*=SZ
# in fringe: every '+N' bang-depth literal and the clamp max (13) scale by SZ
```

- [ ] **Step 2 — Render & view.** Run `py py/gen_sprites.py`; Read both PNGs.
  Expected: hair shows finer lock detail (more, thinner strands), colored highlights (no
  white), per-style hairlines, no dark forehead stripe.

- [ ] **Step 3 — Iterate** thresholds (`j/h/H/x` cutoffs, light dir, ridge weight) until the
  hair reads like the reference at the new size. Acceptance: matches the approved look,
  finer; validate passes.

- [ ] **Step 4 — Commit.**

```bash
git add py/gen_sprites.py
git commit -m "feat: scale hair cel-shading detail to new resolution"
```

## Task 8: World-scale (K=SZ=3) + responsive canvas + position constants

> **Decision (user, Task 1 checkpoint):** SZ=3 **and** a responsive dashboard. Crisp pixel art
> needs an integer sprite scale, so to gain detail without sprites overflowing the rooms we
> render the whole scene at higher internal resolution (world ×`K`, `K`=`SZ`=3) and make the
> canvas **scale-to-fit the viewport** — large screens stay crisp, small ones downscale the
> whole sheet. Approach: in `css/style.css`/`office.html` set the canvas
> `max-width:100vw; max-height:100vh; width:auto; height:auto; image-rendering:pixelated`
> (centered); in `js/app.js` multiply world coords (`ROOMS`/desks/`WORK_POS`/`SIT_POS`/
> `QUEUE_SPOTS`/`NAV_OBSTACLES`/decor) by `K` — or `ctx.scale(K,K)` once at the top of `draw()`
> and leave coords as-is (simpler; check line widths/text) — and draw sprites at
> `spriteScale = SZ` 1:1 with world pixels. The steps below then re-anchor/verify.

**Files:** Modify `office.html` + `css/style.css` (responsive canvas) and `js/app.js`
(canvas `W`/`H`, world `K`-scale, `agents` `spriteScale`, `WORK_POS`, `SIT_POS`, `QUEUE_SPOTS`,
`drawChairBack` (~L2660 cover box), `drawAgent` (~L1908 sizing/label/shadow), y-sort,
`NAV_OBSTACLES`).

- [ ] **Step 1 — Set `spriteScale`.** The sprites are now `SZ`× taller; decide on-screen size
  (the reference shows larger characters). Set each agent's `spriteScale` so `gridRows *
  spriteScale` is the intended on-screen height; `drawAgent` already derives `sprW/sprH` from
  `grid[0].length * sc` and `grid.length * sc`, so only `sc` changes there.

- [ ] **Step 2 — Re-anchor desk/seat positions.** `drawAgent` places the sprite at
  `y = pos.y - sprH` (feet at `pos.y`) and `x = pos.x - sprW/2`. With a taller sprite, verify
  seated agents sit at the monitor (adjust `SIT_POS` y) and standing agents stand at the desk
  (`WORK_POS`). Adjust `QUEUE_SPOTS` (coffee/sofa) so agents don't overlap furniture.

- [ ] **Step 3 — Resize the chair-back cover.** In `drawChairBack`, the `cw`/`h` box was sized
  for the old sprite; scale it so it still covers the seated agent's lower body without
  burying the head.

- [ ] **Step 4 — Verify live.** Reload `office.html`. Expected: agents walk, stand at desks,
  sit at monitors, and the done-flash works — all without clipping furniture or floating.
  Trigger a tool call (or seed `agent-events.json`) to watch a walk→work→idle cycle.

- [ ] **Step 5 — Commit.**

```bash
git add js/app.js
git commit -m "fix: rescale sprite size and re-anchor desk/seat/queue positions"
```
